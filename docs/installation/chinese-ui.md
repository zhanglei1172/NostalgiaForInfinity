# 中文管理后台

仓库内的 `frontend/` 提供基于 FreqUI 3.2.1 的中文界面，默认使用简体中文，顶部语言选择器支持切换 English。
语言偏好保存在浏览器中，切换时未提交的表单会重置。

## 更新 Docker 镜像

在仓库根目录执行以下命令。只有构建成功后，才会重新创建机器人容器：

```bash
docker compose build freqtrade &&
  docker compose up -d --no-build --pull never freqtrade
```

如果 Docker Hub 加速源出现镜像元数据校验错误，可以分别指定 Freqtrade 和 Node 的官方直连地址：

```bash
docker compose --progress plain build \
  --build-arg sourceimage=registry-1.docker.io/freqtradeorg/freqtrade \
  --build-arg nodeimage=registry-1.docker.io/library/node \
  freqtrade &&
  docker compose up -d --no-build --pull never freqtrade
```

打开原有后台地址，强制刷新页面，例如 `Ctrl+Shift+R`。本机模拟盘若使用 `18080:8080` 映射，地址为
`http://127.0.0.1:18080`。用户名、密码、模拟盘资金和交易数据库沿用现有配置与 `user_data/` 挂载。
容器重新创建期间交易循环会短暂中断。

## OKX 与默认停止状态

默认 Compose 使用 OKX 现货模拟盘：`dry_run=true`，不需要交易所 API 密钥，使用公开行情。
新账本为 `user_data/nfi-paper-okx.sqlite`；原 Binance 数据库和 `user_data/research/` 保留。
两套服务默认在容器启动／重建后保持停止，需在网页手动点击“启动”。
可在「设置 → 机器人启动」单独为当前机器人开启自动启动，详见下节。
**停止状态也停止已有持仓管理**；有持仓时如需继续管理退出，可使用“暂停开仓”，但它也会停止加仓。

默认直接连接 OKX，不启动代理容器。容器 DNS 默认为 `1.1.1.1`，可通过私有 `.env` 中的
`NFI_DNS_SERVER` 更换为可用的 DNS 服务；此设置不修改宿主机 DNS。
若之前启用了代理，从私有 `.env` 的 `COMPOSE_FILE`
中移除 `docker-compose.proxy.yml`，然后重建服务并清理旧代理：

```bash
docker compose -f docker-compose.yml -f docker-compose.override.yml \
  up -d --no-build --pull never --remove-orphans
```

重建后机器人按已保存的启动设置运行，未配置时保持停止。直连检查应在容器内访问 OKX API；浏览器能打开交易所网页，
不能单独证明容器能获取交易行情。正常响应的 `code` 应为 `0`：

```bash
docker compose exec freqtrade curl --noproxy '*' --connect-timeout 5 --max-time 15 \
  https://www.okx.com/api/v5/public/time
```

本机 OKX 直连超时、主机存在 `127.0.0.1:7890` HTTP 代理时（Linux）：

```bash
docker compose -f docker-compose.yml -f docker-compose.override.yml -f docker-compose.proxy.yml \
  up -d --no-build --pull never freqtrade
```

该文件通过 Docker 网桥 `172.17.0.1:17890` 转发到本机代理，不修改系统代理。
网桥／代理端口不同可设置 `NFI_PROXY_BIND`／`NFI_PROXY_HOST_PORT`。
后续命令应继续携带这三个 `-f` 文件，或将其加入私有 `.env` 的 `COMPOSE_FILE`（Linux 下用冒号分隔）。
直连正常时不需要此文件。OKX 模拟盘不是 OKX 交易所模拟 API，不应填入真实密钥。

## 容器启动后自动启动机器人

进入「设置 → 机器人启动」，切换“容器启动／重启后自动启动机器人”，输入当前管理员密码并保存。
默认关闭；开启时需确认自动交易提示，实盘还要求交易账户已成功加载。

- 设置保存在当前机器人的 `user_data/.nfi-startup.json`，权限 `0600`；模拟盘与实盘分别保存，各浏览器共用。
- 修改开关不会立即启动、停止机器人，也不会重启容器；下次容器启动、重启或重建时生效。
- 关闭时启动为 `stopped`；开启时启动为 `running`，策略可自动产生订单。
- 保存实盘账户、重新加载配置或应用配方后仍保持停止，不会借此触发自动启动。
- 手动停止或暂停开仓不改变此开关；若不希望容器重启后恢复交易，需要同时关闭自动启动。
- 实盘未初始化、账户配置加载失败或启动设置损坏时不会自动交易。

## Bark 服务端通知

在当前机器人的「设置 → Bark 通知」中配置，模拟盘与实盘独立保存：

1. 在 iPhone 安装 Bark，复制包含设备密钥的完整推送地址，例如 `https://api.day.app/你的设备密钥`。
   也支持自建服务，如 `https://bark.example.com/你的设备密钥`；使用带路径前缀的服务时保留此前缀。
2. 填写地址，选择通知事件、收益／亏损阈值和冷却时间，开启通知，输入当前管理员密码保存。
3. 再次输入管理员密码，点击“发送 Bark 测试通知”，确认手机收到。测试使用已保存地址，自动通知关闭时也可测试。

- 支持**收益达标、亏损达标、机器人状态变化**，可分别勾选。默认关闭，预设收益 `5%`、亏损 `3%`，
  同类事件冷却 `60` 分钟，可调 `5–1440` 分钟。亏损填写正数，`3` 表示收益率 `≤ -3%`。
- 收益率为**当前机器人账本累计交易盈亏／机器人起始资金**，含手续费、部分退出收益和剩余持仓浮盈亏，
  沿用 Freqtrade 盈亏口径；不是月收益率，也不是账户充值、提现带来的余额变化。
- 每 `60` 秒由现有容器的后台任务检查，关闭浏览器后继续运行；机器人停止时仍检查，但实盘需先完成交易账户初始化。
  不会自动开仓、平仓或修改机器人状态。无需新容器。
- 首次开启或修改阈值时，当前值已达标也会通知。同一阈值持续达标只发一次，离开触发区间再越线且冷却结束后才重发。
  去重状态跨容器重启保存；发送失败间隔 `5` 分钟重试，测试消息每分钟最多一次。
- 状态通知只覆盖监测到的运行／停止／暂停开仓变化，首次检查不发状态通知。
  容器停机及两次检查间的短暂变化无法报告；容器启动前的历史状态变化不会逐条补发。
- 页面可刷新查看最近检查的收益率及最近 `20` 次发送结果；成功表示 Bark 已接收，实际送达依赖 Bark 和 iOS 设置。
- 地址与设备密钥保存到当前机器人的 `user_data/.nfi-bark.json`（`0600`），不回填网页，不写入 Compose 或浏览器存储。
  留空保留原地址；先关闭自动通知，再勾选删除并保存可清除地址。此文件需要作为私密配置备份。

## 策略动态

从侧栏或总览进入“策略动态”（`/activity`）：

- **当前开仓状态**：区分停止、暂停开仓、持仓名额及全局保护锁定。
- **最近分析信号**：读取候选币对已缓存的 5m K 线、原始进出场标签及币对锁定；显示缓存过期或尚未分析。
- **最近成交**：从当前账本读取最近 30 笔有成交数量的订单，包含部分成交；最终退出原因只归属于最终退出订单。
- **已记录的开仓拒绝**：识别 X8 已明确记录的滑点、模式名额和名单拦截，最多 100 条。
  这部分在重启或配置重载后清空；成交仍持久保存在数据库。

页面每 15 秒按自动刷新设置更新，也可手动刷新。它只读、不重跑指标或调用下单。
信号不代表实际成交；没有信号不等于某个具体指标失败，未记录的拒绝原因不会编造。
停止状态下可能保留旧分析，需结合 K 线时间和状态阅读。

## 实盘交易账户配置

独立实盘管理后台为 `http://127.0.0.1:18081`。首次访问在网页创建管理员账号，
登录后进入“交易账户”，配置 OKX API Key、Secret、Passphrase 和初始资金预算。
Docker 启动命令和 Compose 不包含账户凭据或预算；密钥保存后不会回填浏览器。
真实余额通过“验证连接并读取余额”读取，不提供伪造余额或网页划转功能。
保存及应用后机器人保持停止，需手动启动。详细流程见 [OKX 现货实盘准备](live-okx-spot.md)。

## 账户与密码

打开侧栏或右上角账户菜单中的“账户与安全”（也可从“设置”进入）：

- **修改密码**：输入当前密码、新密码和确认密码。新密码为 12–128 个字符，支持中文，不能包含控制字符。
- **退出当前设备**：清除此浏览器保存的登录信息。
- **退出所有设备**：验证当前密码并确认后，撤销全部访问／刷新令牌及浏览器 WebSocket 登录。

改密后所有设备都需要用新密码重新登录，机器人交易继续运行。当前版本管理的是单个机器人管理员账户。
首次使用沿用配置／`.env` 中的用户名和密码。首次改密或退出所有设备后，会在挂载的
`user_data/.nfi-account.json` 中保存 scrypt 密码哈希和会话签名密钥（文件权限 `0600`），不保存新密码明文。
此文件在容器重建后继续生效，并优先于 `.env` 中的登录凭据；仅修改 `.env` 不会重置已管理的密码。
请将该文件作为私密配置备份；若目录不可写，页面会提示失败并保留原密码。

忘记密码时，需要有主机权限的管理员恢复，网页不提供绕过当前密码的重置入口：

1. 执行 `docker compose stop freqtrade`。
2. 在私有配置／`.env` 中设置新的启动登录密码，并将 `api_server.jwt_secret_key`
   （环境变量 `FREQTRADE__API_SERVER__JWT_SECRET_KEY`）替换为新随机值，例如使用 `openssl rand -hex 32` 生成。
3. 将 `user_data/.nfi-account.json` 移到仓库外的安全位置；不要改动交易数据库。
4. 执行 `docker compose up -d --no-build --pull never freqtrade`，使用配置中的新密码登录。

恢复会短暂停止机器人，并使旧会话失效；恢复后可再次从网页设置密码。

## 密码错误与限时冻结

所有机器人的 Web 登录、HTTP Basic 验证、修改密码、退出全部设备、启动设置、Bark、实盘账户及配方应用，
共用当前机器人的密码失败计数：**5 分钟内连续错误 5 次，第 5 次即冻结 5 分钟**。

- 冻结期间即使密码正确也不验证；返回 `429`，响应体 `retry_after` 和 `Retry-After` 头给出剩余秒数。
  冻结期间的请求不延长冻结时间，期满自动恢复；未被冻结时，正确验证会清零连续失败次数。
- 登录及设置页显示倒计时，停用需要验证密码的按钮；刷新页面后从服务端恢复冻结状态。
  换用户名、伪造转发 IP、切换验证入口或重建容器均不能清零计数。
- 冻结只影响密码验证，已签发的有效 JWT 会话、只读查询、令牌刷新和交易循环继续运行。
  模拟盘、实盘分别计数，互不锁定。首次创建实盘管理员的无效提交使用独立的相同限额。
- 记录保存在当前机器人 `user_data/.nfi-auth-guard.json`（`0600`），只含时间与计数，不存密码、用户名或 IP。
  保留该挂载即可跨重启继续生效；记录损坏或不可写时验证返回 `503`，请修复存储后重试。
- 当前项目没有独立的配对码验证入口。首次管理员创建仍沿用仅允许本地同源访问的流程。

## 新版资金看板

打开“总览”可查看账户净值、初始资金变化、已实现盈亏和持仓交易盈亏。
资金曲线可切换 24 小时、7 天、30 天或全部记录，并展开数据表。

黄色曲线是机器人保存的每日钱包估值；黄色虚线是旧版重建记录，不含历史浮盈亏。
青色曲线是看板打开时采集的实时净值，每分钟刷新，以 5 分钟粒度保存在当前浏览器，最多 31 天。
关闭页面期间不会采集；长时间缺测会显示断线。更换浏览器或清理站点数据会失去这部分观测记录。
自动刷新关闭时可点击“刷新”手动采集。账户指标仅针对当前机器人，资金变化可能包含出入金。

## 按月回测收益

侧栏的“策略库”可查看 X6、X7、X8 的源码并选择用于回测的策略。“回测”入口在模拟盘模式下也可使用：

1. 选择策略、初始资金和起止日期，默认最近 3 个完整月份，以控制扩大币池后的内存占用。日期按 UTC，结束日期不含当天。
2. 点击“下载历史行情”，等待数据准备完成。首次下载会自动补齐 5m、15m、1h、4h、1d 的指标预热数据。
3. 点击“开始回测”。完成后查看每月净收益、收益率、交易数、胜率，或导出 CSV。
4. 重启后，可在“已保存的回测结果”中重新加载结果。

报告中的“回撤与修复”优先读取回测归档的钱包估值序列，展示最大比例回撤、最大金额回撤、
最大比例回撤的修复时间及最长水下时间，并提供可缩放的回撤曲线。比例最大和金额最大的回撤可能发生在不同区间。
下跌持续时间是高点到低点；修复时间是下跌前最后一次前高到首次恢复该前高，另显示触底后修复用时。
尚未修复时明确标记，并将水下时长观察至回测结束。时间统一按 UTC，精度取决于保存的估值采样。

已有结果若包含钱包记录，可直接重新选择查看，无需重跑。缺少序列时优先显示引擎钱包汇总，
修复时间保留为“暂无数据”；只有最终平仓数据时会标明重建口径，可能遗漏持仓浮亏及分批退出的时间影响。
引擎原有 `drawdown_duration` 是高点到低点，不能用作回撤修复时间。

`docker compose up -d --no-build --pull never freqtrade` 会同时启动独立的 `backtesting` 服务。
仅主后台的 `18080` 端口对本机开放，回测请求经主后台认证后转发；无需另注册账户。
OKX 回测数据与结果存于 `user_data/research-okx/`，不使用模拟盘交易数据库。
修改启动登录凭据后，应重新创建两个服务，确保内部连接凭据一致。

默认测试范围是 OKX 现货 40 个固定 USDT 币对，单边手续费 0.1%，最多六笔持仓。
可在“策略配方”修改，保存后无需重启回测服务；更换币池后请补下载历史行情。
这与模拟盘的动态币池不同，页面会显示实际测试币对和时间，不能把其收益直接当作模拟盘的预期。
月收益按平仓月份归集，包含手续费及期末强制平仓，不含月末持仓浮盈亏，也未额外模拟滑点。
不足整月会明确标注，历史回测不保证未来固定收入。

## 策略配方

实盘后台也提供策略库、回测和策略配方入口。实盘配方采用独立草稿、参数对比及密码确认应用，
支持恢复上一份配方；不与模拟盘自动同步。详细操作见 [OKX 实盘配置](live-okx-spot.md#策略库回测与实盘配方)。
下面的保存与应用说明针对模拟盘。

打开侧栏“策略配方”，或直接访问 `/recipes`。这是 OKX 现货 NFI X8 的模拟验证配置，
依据仓库建议的 6–12 个持仓、40–80 个币对建立基线，没有通过收益最大化搜索选择参数。
公共默认值在 `webserver_extensions/nfi_research/recipe_defaults.json`，OKX 币对替换在 `recipe.py` 的 `exchange_defaults`：

| 参数 | 默认值 | 作用范围 |
| --- | --- | --- |
| 最大持仓数 | 6 | 模拟盘及回测，允许 6–12 |
| 可用资金比例 | 99% | 两者；预留 1%，不是回撤上限 |
| 动态币池上限 | 40 | 仅模拟盘，允许 40–80 |
| 最低上市天数 | 60 天 | 仅模拟盘 |
| 最低 24 小时成交量 | 500 万 USDT | 仅模拟盘 |
| 最大买卖价差 | 0.5% | 仅模拟盘 |
| 单边手续费 | 0.1% | 两者，买入和卖出各计费 |
| 入场滑点容忍度 | 2% | NFI 入场保护，不是历史滑点成本模型 |

模拟盘沿用仓库黑名单、价格及区间稳定性筛选：从成交量前 130 名中筛选，再保留最多 40 个。
过滤后可能不足 40 个；回测使用独立的固定 40 币列表，可调整为 3–80 个明确的 `BASE/USDT` 币对。
固定币池不复现历史成交量、价差、币龄筛选，用当前存续币种回测存在幸存者偏差，
因此不能把固定币池回测视作动态模拟盘的等价结果。

1. **保存用于回测**：持久保存配方，下次下载及回测读取最新版本；正在运行的任务保留启动时的快照。
2. **应用到模拟盘**：保存后单独点击并确认，通过 Freqtrade 配置重载生效。页面等待机器人报告版本，
   沿用交易数据库、初始模拟资金及持仓，已有持仓随后使用新配置。重载后回到停止状态，需手动启动。
3. **恢复默认值**：只填入表单，仍需保存及应用；“重新加载已保存配方”可放弃未保存编辑。

已保存版本、当前模拟盘版本和生效参数分别显示，跨浏览器同时编辑时会拒绝覆盖过期版本。
配方原子写入挂载的 `user_data/recipes-okx/`；`saved.json` 供研究读取，`active.json` 在模拟盘启动及重载时读取，
`previous-saved.json`、`previous-active.json` 保留上一版。配方不包含登录凭据。
这些受控参数优先于同名 `.env` 配置，其余配置继续沿用原文件。
仅在 Compose 显式设置 `NFI_RECIPE_ROLE=paper` 时启用模拟盘配置覆盖，实盘不可应用；配方后端兼容 OKX 和 Binance 现货。

保持 5 分钟周期、退出信号、允许亏损退出及策略减仓／止损逻辑；不提供任意 JSON、杠杆或信号阈值编辑。
新回测会清理旧币池行情缓存，并检查所有币对与周期的行情起止覆盖；缺少行情时先提示下载，
防止引擎静默跳过新币对。更换配方后会清除旧的“行情已准备好”状态。
结果压缩包内的配置记录配方版本与启动参数。
首次验证建议先用一个完整月份估算下载时间和内存，再扩大日期；40 个币对的一年数据比原先三币测试耗费更多资源。
对比参数时固定交易所、模式、币池、日期、手续费及保护设置，并使用独立验证期和持续模拟盘观察，避免只看最好的月份。

## 界面范围
